# Phase 2: 架构设计 — 绿地项目

> 适用：从零开始的新项目开发

## 绿地项目重点

- 设计全新架构
- 选择技术栈
- 建立开发规范

## 执行步骤

### Step 1: 选择应用架构

| 架构       | 适用场景 | 团队规模 |
| ---------- | -------- | -------- |
| 单体架构   | 小型项目 | < 5 人   |
| 模块化单体 | 中型项目 | 5-15 人  |
| 微服务     | 大型项目 | > 15 人  |

### Step 2: 设计数据模型

1. **核心实体**

   ```markdown
   ## 数据模型

   ### 用户表 (users)

   | 字段  | 类型    | 说明 |
   | ----- | ------- | ---- |
   | id    | UUID    | 主键 |
   | email | VARCHAR | 唯一 |
   ```

2. **关系设计**
   - 一对一、一对多、多对多
   - 索引设计
   - 规范化 vs 反规范化

### Step 3: 设计 API

1. **RESTful 设计**
   | 端点 | 方法 | 说明 |
   |------|------|------|
   | /users | GET | 列表 |
   | /users/:id | GET | 详情 |
   | /users | POST | 创建 |

2. **错误处理**
   ```json
   {
     "error": {
       "code": "VALIDATION_ERROR",
       "message": "邮箱格式不正确"
     }
   }
   ```

### Step 4: 建立开发规范

1. **代码风格**
   - ESLint + Prettier
   - TypeScript 严格模式
   - 提交信息规范

2. **Git 工作流**
   - GitHub Flow
   - PR 必须经过审查
   - 主分支受保护

## 输出物

- `.specs/{change-id}/DESIGN.md` — 设计文档
- 架构决策记录 (ADR)
- 开发规范
