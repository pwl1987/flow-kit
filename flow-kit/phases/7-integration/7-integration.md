# Phase 7: Integration - 集成与归档

## 触发条件
{{TRIGGER}}

- Phase 6 评审通过
- 用户显式启动集成流程
- 所有评审问题已修复

## 核心行为
{{CORE_BEHAVIOR}}

1. **分支整合**：将开发分支合并到主分支
2. **冲突解决**：处理合并过程中的冲突
3. **最终验证**：合并后运行完整测试
4. **版本标记**：为发布版本创建 tag
5. **变更归档**：归档本次变更的所有相关文档
6. **通知发布**：向相关方发布变更完成通知

## 边界情况
{{BOUNDARY_CASES}}

- **合并冲突**：复杂的合并冲突需要手动解决
- **发布失败**：测试失败时阻止发布并回滚
- **回滚需求**：需要回滚到前一版本
- **增量发布**：部分功能需要分批发布
- **紧急发布**：需要跳过部分流程的紧急发布

## 输出物
{{OUTPUTS}}

- **合并记录**：分支合并历史
- **版本发布包**：可部署的版本产物
- **变更日志**：CHANGELOG 条目
- **归档包**：完整的变更文档归档
- **后续 Phase 入口确认**：确认流程结束或进入 8-rollback
