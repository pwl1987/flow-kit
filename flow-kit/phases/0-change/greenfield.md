# Phase 0: 变更立项 — 绿地项目

> 适用：从零开始的新项目开发

## 绿地项目特点

- 空白目录，无历史包袱
- 可以自由设计架构
- 重点：项目愿景、技术选型、规模评估

## 执行步骤

### Step 1: 项目愿景定义

1. **核心问题**
   - 这个项目要解决什么问题？
   - 目标用户是谁？
   - 成功标准是什么？

2. **输出项目愿景文档**

   ```markdown
   ## 项目愿景

   [一句话描述产品目标]

   ## 目标用户

   [目标用户群体]

   ## 成功指标

   - [指标 1]
   - [指标 2]
   ```

### Step 2: 技术栈选择

1. **后端框架选择**
   | 框架 | 适用场景 | 团队要求 |
   |------|----------|----------|
   | Node.js + Express | 快速开发、团队熟悉 | 低 |
   | Python + FastAPI | AI 集成、数据处理 | 中 |
   | Go | 高性能、微服务 | 高 |
   | Java Spring Boot | 企业级、稳定 | 高 |

2. **前端框架选择**
   | 框架 | 适用场景 | 特点 |
   |------|----------|------|
   | React + Vite | 生态最全 | 上手较难 |
   | Vue 3 | 简单项目 | 上手简单 |
   | Svelte | 性能优先 | 小众 |

3. **数据库选择**
   | 类型 | 适用场景 | 代表 |
   |------|----------|------|
   | 关系型 | 标准业务、事务 | PostgreSQL |
   | 文档型 | 灵活结构 | MongoDB |
   | KV | 缓存、高性能 | Redis |

### Step 3: 规模评估

| 级别 | 改动范围   | 推荐流程                 |
| ---- | ---------- | ------------------------ |
| L0   | 1-3 文件   | 极简模式，跳过 Phase 2-3 |
| L1   | 4-10 文件  | 标准 9 阶段 (Phase 0-8)              |
| L2   | 11-30 文件 | 完整流程 + 设计评审      |
| L3   | > 30 文件  | 多代理并行               |

### Step 4: 护栏配置

**绿地项目可使用核心护栏**

```bash
/flow-kit:guard minimal
```

### Step 5: 生成 Change ID

```bash
./flow-kit.sh change init "变更描述"
```

## 输出物

- `.specs/{change-id}/CHANGE.md` — 变更摘要
- 项目愿景文档
- 技术选型决策
- 规模评估
