# init-change

> flow-kit v2.5.0 命令

## 描述

自动化变更初始化。一条命令完成：

1. 自动生成语义化 change-id（从描述提取关键词 + 日期）
2. 自动创建固定目录结构（`.specs/{change-id}/` 含 5 个标准文件骨架）
3. 自动检测项目类型（棕地/绿地）
4. 自动推荐护栏配置（带原因解释）
5. 输出下一步建议

## 用法

```bash
/flow-kit:init "变更描述"
```

## 示例

```bash
# 初始化一个用户反馈功能变更
/flow-kit:init "添加用户反馈中心模块"

# 预期输出：
# 📋 项目类型: brownfield
# 🛡️ 推荐护栏配置: 棕地项目 - 启用全部护栏 B1-B6
#    原因: 已有代码库，需保护现有功能不破坏
#    命令: /flow-kit:guard full
# ✅ 变更规格已创建: .specs/用户反馈中心-20260511/
# 📌 下一步建议:
#    1. [推荐] 启动变更立项: /flow-kit:phase-0
```

## 项目类型推荐护栏

| 项目类型 | 推荐护栏                  | 原因                           |
| -------- | ------------------------- | ------------------------------ |
| 棕地项目 | `/flow-kit:guard full`    | 已有代码库，必须全部启用 B1-B6 |
| 绿地项目 | `/flow-kit:guard minimal` | 新项目无历史包袱，可适度放宽   |

## 固定目录结构

`.specs/{change-id}/` 目录包含：

| 文件           | 说明                                     |
| -------------- | ---------------------------------------- |
| CHANGE.md      | 变更摘要（变更类型、影响范围、关联需求） |
| REQUIREMENT.md | 需求文档（验收标准 Given/When/Then）     |
| DESIGN.md      | 架构设计（技术方案、候选对比、回滚方案） |
| TASK.md        | 任务列表（任务拆解、依赖图）             |
| PROGRESS.md    | 进度记录（Phase 0-7 完成情况）           |

## 下一步建议机制

每个命令完成后自动输出：

```
📌 下一步建议:
   1. [推荐] /flow-kit:phase-0
      原因: 进入 Phase 0 进行影响范围评估
   2. [可选] /flow-kit:phase-1
      原因: 如果需求已明确，可跳过 Phase 0

💡 输入 /flow-kit:next 可自动推进到下一步骤
```

## 变更 ID 格式

`{slugified-description}-{YYYYMMDD}`

示例：

- "添加用户反馈中心" → `用户反馈中心-20260511`
- "fix login bug" → `fix-login-bug-20260511`
