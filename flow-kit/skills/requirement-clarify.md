# Requirement Clarify Skill

## WHEN_TO_USE
- Phase: 1-requirement
- Trigger: 用户提出模糊/不完整/存在歧义的需求

## HOW_TO_USE

### Phase 1: Alignment Check（对齐检查）
**目的**: 确保对目标、范围、约束的理解一致

**执行步骤**:
1. 梳理项目目标（Goal）和成功标准
2. 明确范围边界（Scope）和排除项
3. 确认约束条件（Constraints）
4. **触发 ubiquitous-language.md 进行术语冲突扫描**
5. 退出检查：
   - 客观检查：目标/范围/约束已梳理 + 术语无冲突（自动扫描）
   - 用户确认：显式表达「理解一致」

**清窗触发条件**:
- 目标/范围失败 > 2 次
- 高优先级术语冲突连续 2 次

### Phase 2: Deep Dive（一次一问）— 逐点深入
**目的**: 对每个需求点单独深入澄清

**核心模式**: 「一次一问」— 上一问题未澄清不进入下一问题

**GRILL-ME 扩展模板**（每个需求点）:
| 维度 | 问题 | 目的 |
|------|------|------|
| **G**oal | 这个功能的最终目标是什么？ | 理解真实需求 |
| **R**ole | 谁会使用这个功能？他们的背景？ | 确定用户画像 |
| **I**nput | 触发条件的输入是什么？ | 明确数据边界 |
| **L**imitation | 有什么技术或业务限制？ | 约束条件 |
| **L**ogic | 核心业务逻辑是什么？ | 处理规则 |
| **M**etric | 如何判断成功？验收标准？ | 可验证性 |
| **E**dge | 边界条件和异常情况？ | 完整性 |

**执行格式**:
```markdown
## Deep Dive — 需求点 #N/M

**需求：** [需求描述]

**当前问题：** [歧义点]

---

**Q1 (Goal):** [问题]
- [选项或等待用户回答]
[等待用户回答后进入 Q2]
```

**退出标准**:
- 客观检查：所有需求点一次一问完成 + 术语冲突已解决
- 用户确认：显式表达「细节无异议」

**清窗触发条件**:
- 同一需求点反复澄清 > 2 次
- 未解决歧义积累 > 3 个

### Phase 3: Verification & Documentation（验证与文档）
**目的**: 生成完整文档 + 验收标准 + 用户最终确认

**执行步骤**:
1. 生成完整需求文档
2. 输出验收标准（Given/When/Then 格式）
3. 列出边界条件和异常处理
4. 用户最终确认

**退出标准**:
- 客观检查：完整文档 + 可验证验收标准
- 用户确认：显式表达「可作后续依据」

### 强制清窗规则

**清窗分级**:
| 级别 | 场景 | 后果 |
|------|------|------|
| 软清窗（默认） | 歧义积累超阈值 | 退回 Alignment Check，保留已澄清内容 |
| 硬清窗（极端） | 连续 2 次软清窗仍无法对齐 | 终止流程，标记「无法达成共识」 |

**决策机制**: 自动预警 + 用户确认

**输出格式**:
```markdown
## [流程预警：触发软清窗条件]

**原因：**
- [具体触发原因]

**当前状态：**
- 已澄清：X/Y 需求点
- 待澄清：Z 个歧义点

**请选择：**
1. [执行软清窗] — 退回 Alignment Check，保留已澄清内容
2. [继续讨论] — 暂不清窗，继续当前阶段
3. [执行硬清窗] — 极端情况，终止当前流程
```

## EXAMPLE

**原始需求**：
> "系统需要安全地处理用户数据"

**三阶段执行示例**:

### Phase 1: Alignment Check
```
[目标]: 用户数据安全存储和访问控制
[范围]: 用户个人数据（不含公开信息）
[约束]: 符合当地数据保护法规

[触发 UL 扫描]
术语冲突检测报告: 无冲突
→ 用户确认「理解一致」
```

### Phase 2: Deep Dive（一次一问）
```
[需求点 #1/3]

**Q1 (Goal):** "安全地"具体指什么？
A: 防止未授权访问、加密存储、审计日志

**Q2 (Role):** 哪些用户角色需要访问？
A: 普通用户（上传）、管理员（查看）、审计员（报告）

[继续直到所有需求点澄清]
```

### Phase 3: Verification & Documentation
```
[输出完整需求文档]

## 验收标准

### AC-1: 数据加密
- **Given** 用户上传文件
- **When** 文件存储时
- **Then** 使用 AES-256 加密

### AC-2: 访问控制
- **Given** 普通用户
- **When** 尝试访问他人数据
- **Then** 返回 403 Forbidden

[用户最终确认]
```

## NOTES

### 常见陷阱
| 陷阱 | 描述 | 解决方法 |
|------|------|----------|
| 歧义名词 | "用户"、"系统" 指代不明 | 要求明确具体对象 |
| 未定义成功 | 没有验收标准 | 应用 Given/When/Then |
| 隐含假设 | 跳过看似 obvious 的细节 | 检查所有假设 |
| 范围蔓延 | 需求越做越大 | 明确 MVP 边界 |

### 验证检查
- [ ] 所有名词有唯一指代
- [ ] 每个动词可执行且可测试
- [ ] 验收标准包含量化指标
- [ ] 边界情况明确列出
- [ ] 三阶段退出标准均满足

### 与 ubiquitous-language.md 联动
- Alignment Check 结束前触发术语冲突扫描
- Deep Dive 发现术语冲突时暂停，调用 UL 处理
- Verification 前确认所有冲突已解决
