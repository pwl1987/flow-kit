# 任务 1.2: error-handler 模块重写

## 依赖
1.1（需要 paths 模块提供日志目录路径）

## 目标
将 `lib/error-handler.sh`（244行）重写为 `src/lib/error-handler.mjs`。提供结构化日志、错误码常量、错误聚合等核心功能。

## 实现步骤

### RED（测试先行）
1. 阅读 `lib/error-handler.sh`，提取所有函数和错误码定义
2. 创建 `tests/unit/error-handler.test.mjs`
3. 编写测试用例：
   - `logInfo(module, msg)` 输出 INFO 级别日志，含时间戳和模块名
   - `logWarn(module, msg)` 输出 WARN 级别日志
   - `logError(module, msg)` 输出 ERROR 级别日志
   - `die(code, module, msg)` 记录错误并以指定退出码终止（可 mock process.exit）
   - `checkResult(code, module, type)` 根据错误类型选择处理策略
   - `safeExit(code)` 注册退出处理，确保日志落盘
   - `getTimestamp()` 返回 ISO 格式时间戳
   - `aggregateErrors(errors)` 汇总多个错误为结构化报告
   - 错误码常量（如 ERR_CONFIG, ERR_LOCK, ERR_PHASE 等）导出正确
4. 运行测试确认全部失败（RED）

### GREEN（最小实现）
1. 创建 `src/lib/error-handler.mjs`
2. 定义并导出错误码常量对象
3. 实现 `getTimestamp()` — ISO 格式
4. 实现 `logInfo/logWarn/logError` — 结构化输出到 stderr
5. 实现 `die(code, module, msg)` — 记录后 process.exit(code)
6. 实现 `checkResult(code, module, type)` — 错误分类处理
7. 实现 `safeExit(code)` — 退出处理注册
8. 实现 `aggregateErrors(errors)` — 错误汇总
9. 运行测试确认全部通过（GREEN）
