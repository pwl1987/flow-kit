# 任务 5.4: 批量迁移 Phase 3-8 为 Skill 格式

## 依赖
4.19

## 目标
批量迁移 `phases/3-dev.md` ~ `phases/8-rollback.md` → `skills/phase-{3-8}/SKILL.md`。每个添加 YAML frontmatter。共 6 个 phase。

Phase 映射：
- `3-dev.md` → `phase-3`：开发阶段
- `4-review.md` → `phase-4`：审查阶段
- `5-test.md` → `phase-5`：测试阶段
- `6-deploy.md` → `phase-6`：部署阶段
- `7-monitor.md` → `phase-7`：监控阶段
- `8-rollback.md` → `phase-8`：回滚阶段

## 实现步骤

### RED（测试先行）
1. 编写参数化测试，遍历 phase 3~8，验证每个 `skills/phase-{n}/SKILL.md` 存在
2. 验证每个 frontmatter 包含 `name`、`description`、`disable-model-invocation` 字段
3. 验证每个 `skills/phase-{n}/reference.md` 内容与原始 `phases/{n}-*.md` 一致

### GREEN（最小实现）
1. 为 phase 3~8 各创建目录 `skills/phase-{n}/`
2. 读取各 `phases/{n}-*.md` 原始内容
3. 为每个 phase 创建 `SKILL.md`，添加统一 frontmatter：
   ```yaml
   ---
   name: phase-{n}
   description: {对应描述}
   disable-model-invocation: true
   ---
   ```
4. 将原始内容分别写入 `skills/phase-{n}/reference.md`

### REFACTOR
1. 抽取迁移脚本为可复用函数，避免重复代码
2. 确认 6 个 phase 的 frontmatter 格式完全一致

## 验证
- `npx vitest run` 通过
- `ls skills/phase-{3,4,5,6,7,8}/SKILL.md` 显示 6 个文件
- 逐一 `diff` 原始文件与 `reference.md` 无差异
