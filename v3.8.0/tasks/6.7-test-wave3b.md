# 任务 6.7: Wave 3 剩余模块单元测试

## 依赖
6.1

## 目标
为 Wave 3 剩余模块（dispatch-core.mjs, dispatch-parse.mjs, command-gen.mjs, init-change.mjs, validate-phase.mjs）编写单元测试。

## 实现步骤

### RED（测试先行）
1. 创建 `tests/unit/dispatch-core.test.mjs`，编写 describe('dispatch-core') 测试块
   - 测试命令路由：`dispatch('phase 0')` → 匹配 phase 处理器
   - 测试未知命令：无效命令返回友好错误提示
   - 测试命令优先级：精确匹配优先于模糊匹配
   - 测试批量分发：多个命令按依赖顺序执行
2. 创建 `tests/unit/dispatch-parse.test.mjs`，编写 describe('dispatch-parse') 测试块
   - 测试命令解析：`parseCommand('phase 0 --force')` → `{ action: 'phase', args: { id: 0, force: true } }`
   - 测试参数提取：`--key=value`、`--flag`、位置参数正确提取
   - 测试中文字符：命令含中文时正确解析
   - 测试特殊字符：路径参数含空格/引号时正确处理
3. 创建 `tests/unit/command-gen.test.mjs`，编写 describe('command-gen') 测试块
   - 测试命令生成：`generateCommands()` 输出所有斜杠命令定义
   - 测试命令格式：每个命令包含 name、description、parameters
   - 测试去重：不生成重复命令
   - 测试自定义命令：用户自定义命令正确合并
4. 创建 `tests/unit/init-change.test.mjs`，编写 describe('init-change') 测试块
   - 测试变更初始化：`initChange({ name, description })` 创建变更目录结构
   - 测试目录结构：生成 `.flow-kit/changes/{id}/` 及模板文件
   - 测试重名检查：已存在同名变更时提示而非覆盖
   - 测试 ID 生成：变更 ID 包含时间戳，保证唯一性
5. 创建 `tests/unit/validate-phase.test.mjs`，编写 describe('validate-phase') 测试块
   - 测试阶段验证：`validatePhase(0)` 检查 Phase 0 产出物
   - 测试通过：产出物完整时返回 `{ valid: true }`
   - 测试失败：缺少产出物时返回 `{ valid: false, missing: [...] }`
   - 测试自定义规则：支持阶段特定的验证规则

### GREEN（最小实现）
1. 确认 dispatch-core.mjs 导出 dispatch 函数，接口与测试对齐
2. 确认 dispatch-parse.mjs 导出 parse 函数，接口与测试对齐
3. 确认 command-gen.mjs 导出 generate 函数，接口与测试对齐
4. 确认 init-change.mjs 导出 init 函数，接口与测试对齐
5. 确认 validate-phase.mjs 导出 validate 函数，接口与测试对齐
6. 根据测试失败反馈调整模块导出（仅接口调整，不改逻辑）
