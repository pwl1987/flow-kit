# 任务 1.3: lock 模块重写

## 依赖
1.1（需要 paths 模块提供锁文件目录路径）

## 目标
将 `scripts/dispatch-lock.sh`（160行）重写为 `src/lib/lock.mjs`。使用 Node.js 文件系统操作实现原子锁、并发槽控制，保持 mkdir 原子锁 + PID/TIMESTAMP 双检查机制。

## 实现步骤

### RED（测试先行）
1. 阅读 `scripts/dispatch-lock.sh`，提取所有函数和锁机制
2. 创建 `tests/unit/lock.test.mjs`
3. 编写测试用例：
   - `acquireLock(name, timeout)` 成功获取锁，创建锁目录
   - `acquireLock` 超时后抛出错误
   - `acquireLock` 检测到过期锁（stale）时自动清理并重试
   - `releaseLock(name)` 删除锁目录
   - `releaseLock` 释放不存在的锁时安全返回
   - `isLockStale(name)` 根据 PID+TIMESTAMP 判断锁是否过期
   - `acquireSlot(maxConc)` 在并发限制内获取执行槽
   - `releaseSlot()` 释放执行槽
   - 并发槽满时 `acquireSlot` 阻塞或报错
4. 使用 `os.tmpdir()` 作为测试锁目录，避免污染真实环境
5. 运行测试确认全部失败（RED）

### GREEN（最小实现）
1. 创建 `src/lib/lock.mjs`
2. 实现 `acquireLock(name, timeout)`：
   - 使用 `fs.mkdir()` 原子操作
   - 锁目录内写入 PID 和 TIMESTAMP 文件
   - 失败时检查是否过期，过期则清理重试
3. 实现 `releaseLock(name)` — 递归删除锁目录
4. 实现 `isLockStale(name)` — 读取 PID（检查进程存活）和 TIMESTAMP（检查超时）
5. 实现 `acquireSlot(maxConc)` / `releaseSlot()` — 基于锁文件计数的并发控制
6. 运行测试确认全部通过（GREEN）

### REFACTOR
1. 检查锁目录清理的边界情况（权限不足、磁盘满等）
2. 考虑添加锁泄漏保护（进程异常退出时的清理）

- 锁机制在高并发场景下不会死锁
- 过期锁能被正确识别和清理
