# 任务 6.8: MCP 核心工具集成测试

## 依赖
6.2-6.7

## 目标
为 12 个 MCP 核心工具编写集成测试。每个工具独立测试：status/version/health/recall/metrics/validate/phase/init/dispatch/shellcheck/register。验证 MCP 协议输入输出格式正确。

## 实现步骤

### RED（测试先行）
1. 创建 `tests/tools/status.test.mjs`
   - 测试 `status` 工具：输入 `{}` → 输出含 `version`、`phase`、`mode` 字段
   - 验证返回 JSON 符合 MCP 工具响应格式（content 数组 + type: "text"）
2. 创建 `tests/tools/version.test.mjs`
   - 测试 `version` 工具：输入 `{}` → 输出版本号与 `VERSION` 文件一致
3. 创建 `tests/tools/health.test.mjs`
   - 测试 `health` 工具：输入 `{}` → 输出含 `status: "ok"` 及依赖检查结果
4. 创建 `tests/tools/recall.test.mjs`
   - 测试 `recall` 工具：输入 `{query, limit}` → 返回匹配的会话记录
   - 测试空查询：无匹配时返回空数组
5. 创建 `tests/tools/metrics.test.mjs`
   - 测试 `metrics` 工具：输入 `{action: "query", range}` → 返回指标数据
6. 创建 `tests/tools/validate.test.mjs`
   - 测试 `validate` 工具：输入 `{phase, target}` → 返回验证结果
7. 创建 `tests/tools/phase.test.mjs`
   - 测试 `phase` 工具：输入 `{action, phaseId}` → 返回阶段执行结果
8. 创建 `tests/tools/init.test.mjs`
   - 测试 `init` 工具：输入 `{projectName, mode}` → 初始化项目结构
9. 创建 `tests/tools/dispatch.test.mjs`
   - 测试 `dispatch` 工具：输入 `{command, args}` → 路由到正确处理器
10. 创建 `tests/tools/shellcheck.test.mjs`
    - 测试 `shellcheck` 工具：输入 `{files}` → 返回 lint 结果
11. 创建 `tests/tools/register.test.mjs`
    - 测试 `register` 工具：输入 `{}` → 生成斜杠命令注册文件

### GREEN（最小实现）
1. 为每个工具创建共享测试辅助函数：`callTool(name, args)` 模拟 MCP 调用
2. 创建 `tests/tools/helpers.mjs`：提供 mock MCP 传输层
3. 确认所有工具处理器导出 `handle` 函数，接受 `(args)` 返回 MCP 响应
4. 根据测试失败反馈调整工具接口

## 验证
- `npx vitest run tests/tools/` 全部通过
- 每个工具至少 2 个测试用例（正常 + 边界）
- 所有工具响应符合 MCP 协议格式：`{ content: [{ type: "text", text: "..." }] }`
