# 任务 4.7: 工具 init_change

## 依赖
4.1

## 目标
实现 `init_change` 工具，初始化一个新变更（change），创建 `.flow-kit/` 目录结构和 `session-state.json`，支持棕地/绿地条件路由。

## 实现步骤

### RED（测试先行）
1. 编写 `tests/unit/tools/init.test.mjs`
2. 测试 `init_change` 注册，schema 包含 `description`、`type`（brownfield/greenfield）参数
3. 测试绿地模式：创建完整 `.flow-kit/` 目录结构
4. 测试棕地模式：检测已有项目，补充缺失目录
5. 测试 `session-state.json` 初始内容：`{ phase: 0, type, description, createdAt }`
6. 测试重复初始化时返回已有状态而非覆盖
7. 测试目录创建失败时返回友好错误

### GREEN（最小实现）
1. 创建 `src/tools/init.mjs`，导出 `{ register }`
2. 定义 zod schema：`description` string，`type` enum `['brownfield', 'greenfield', 'auto']`
3. 实现 `init_change` handler：
   - `type: 'auto'` → 检测 `git log` 判断棕地/绿地
   - 创建 `.flow-kit/` 目录及子目录（`phases/`、`metrics/`）
   - 写入 `session-state.json` 初始状态
   - 已存在时返回当前状态
4. 返回 `{ initialized, type, phase, projectRoot }` 结构

## 验证
- `vitest run tests/unit/tools/init.test.mjs` 通过
- 绿地模式创建完整目录结构
- 重复调用不覆盖已有状态

- `src/tools/init.mjs`
- `tests/unit/tools/init.test.mjs`
