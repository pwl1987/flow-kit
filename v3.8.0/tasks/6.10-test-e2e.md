# 任务 6.10: E2E 端到端测试

## 依赖
6.8, 6.9

## 目标
编写 E2E 测试。场景：1) MCP Server 启动+工具列表 2) init_change → run_phase(0) → validate 完整流程 3) hook 触发验证（模拟 PreToolUse/PostToolUse/Stop 事件）。

## 实现步骤

### RED（测试先行）
1. 创建 `tests/e2e/server-startup.test.mjs`
   - 测试 MCP Server 启动：子进程启动 `node dist/mcp-server.cjs`，stdout 返回 MCP 握手响应
   - 测试工具列表：发送 `tools/list` 请求 → 返回所有已注册工具
   - 测试工具调用：发送 `tools/call` 请求 → 返回合法响应
   - 测试优雅关闭：发送 SIGTERM → 进程正常退出，无孤儿文件
2. 创建 `tests/e2e/full-workflow.test.mjs`
   - 测试完整工作流：
     1. 调用 `init_change({ project, description })` → 创建变更目录
     2. 调用 `run_phase({ phase: 0 })` → 执行 Discovery 阶段
     3. 调用 `validate({ phase: 0 })` → 验证阶段产物
     4. 检查文件系统：变更目录存在、session-state.json 已更新
   - 测试中断恢复：流程中断后重新调用 `recall` 恢复上下文
3. 创建 `tests/e2e/hooks-trigger.test.mjs`
   - 测试 PreToolUse hook：模拟 `tool_name + file_path` → 返回放行/拦截决策
   - 测试 PostToolUse hook：模拟编辑后 `file_path` → 触发格式化/质量检查
   - 测试 Stop hook：模拟会话结束 → 触发质量门禁 + 通知
   - 测试 hook 链：多个 hook 按顺序触发，前一个拦截后后续不执行

### GREEN（最小实现）
1. 创建 `tests/e2e/helpers.mjs`：E2E 测试辅助函数
   - `startServer()` — 启动 MCP Server 子进程
   - `sendRequest(method, params)` — 发送 MCP JSON-RPC 请求
   - `stopServer()` — 关闭子进程
2. 创建临时测试目录：每个测试用例使用独立 tmpdir，结束后清理
3. 根据测试失败反馈调整 Server 入口、hook 注册逻辑

## 验证
- `npx vitest run tests/e2e/` 全部通过
- Server 启动测试：< 5s 完成
- 完整工作流测试：< 30s 完成
- hook 测试：覆盖全部 5 个 hook 触发点
- 测试结束后无残留进程（`ps aux | grep mcp-server` 无结果）
