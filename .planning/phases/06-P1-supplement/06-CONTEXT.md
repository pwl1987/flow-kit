## Implementation Decisions

### Area A: phases 文件棕地/绿地分支增强

- **D-07:** 保留 Phase 5 D-01 的 4 个检测信号（文件指纹 + Git remote + 业务代码行数 + 绿地判定），仅优化阈值与白名单。未来通过 `.flow-kit/project-type` 新增 `light-brownfield` 字段扩展，不影响现有分支逻辑。

- **D-08:** phases 文件采用混合模式 — 启动时检查 `.flow-kit/project-type` 是否存在，若存在则直接读取；若不存在则触发检测。Guardrails 联动采用"提示 + 快捷命令"模式，用户手动激活。

### Area B: phase-executor 自动清窗机制

- **D-09:** 渐进式压缩机制 — 80% 预算警告，90% 预算提示，100% 预算强制压缩（可选保留历史）。

- **D-10:** 清理粒度 — 清理已完成 phase 的 checkpoint 文件和 logs，核心文档（CONTEXT.md / PLAN.md）保留，归档而非删除。

### Area C: GO.md 智能路由增强

- **D-11:** GO.md 启动时显示 project-type 检测结果摘要 + 推荐 actions + 快捷命令提示。

- **D-12:** 用户覆盖机制 — 命令行覆盖优先（`/flow-kit:project-type [type]`），配置文件为默认值（`.flow-kit/user-config.md`），两种都支持。

### Area D: skills 内容充实

#### D-13~D-18: code-review.md

- **D-13:** 每个检查项增加自动化命令，区分阻断项（必须通过）和警告项（仅提示）。用户可在 `.flow-kit/user-config.md` 自定义检查命令。

- **D-14:** 标准化执行流程：前置自动化检查 → 人工三层审查 → 补充自动化检查 → 输出分级报告（致命/严重/一般/建议 + 通过/不通过判定）。

- **D-15:** 三种 review 深度模板：简化模板（P2/单文件）、标准模板（P1/模块）、深度模板（P0/微服务）。P0 强制使用深度模板。

- **D-16:** 棕地项目自动启用棕地专用模板，增加历史逻辑兼容性 + 依赖风险检查项。

- **D-17:** 深度模板消耗更多 token，自动提示用户提前归档旧文件。

- **D-18:** review 结果自动填充到 PR 描述的审查结果部分。

#### D-19~D-20: debugging.md

- **D-19:** 增加常见错误模式库（Phase 文件格式错误 → 联动 `/flow-kit:validate-phase`；Checkpoint 残留 → 联动 `/flow-kit:reset-checkpoint`）。

- **D-20:** 提供独立日志收集/状态快照脚本，通过 `/flow-kit:debug-snapshot` 调用，支持棕地/绿地场景适配，棕地项目自动关联数据库状态快照。

#### D-21: verification.md

- **D-21:** 三层结构增强 — 分阶段验证门控（Phase1-2 轻量、Phase3-4 基础、Phase5-6 全量）+ 自动化验证流水线（阻断项/警告项区分）+ 验证失败恢复指南（联动一键修复命令）。棕地启用历史兼容性检查，绿地启用标准检查。

#### D-22: requirement-clarify.md

- **D-22:** 模糊需求识别规则 + 量化建议模板 → 可测试性检查 → 验收标准自动生成 → 对接 verification.md 和 code-review.md。MoSCoW/Kano 作为可选扩展。

#### D-23~D-25: task-master.md

- **D-23:** 任务依赖关系图（自动识别 + 用户手动调整）→ 对接 subagent-execution 自动调度并行任务。任务状态与 checkpoint 同步，blocked 触发断点续跑。

- **D-24:** 可选看板视图，不强制默认开启。

- **D-25:** 任务耗时估算预留接口，后续对接历史数据。

#### D-26: subagent-execution.md

- **D-26:** 子代理调度策略（依赖校验 + 自动调度，与 task-master 依赖图联动）+ 资源限制（并发数配置 + 预算动态调整，80% 预算时降为 1 并发，90% 预算强制串行）+ 执行日志（结构化记录 + 归档到 archive/ + 导入成本报告）。

#### D-27~D-29: parallel-dispatch.md

- **D-27:** 任务分组策略（按前端/后端/测试分组，同一类型任务分发到同一子代理，减少上下文切换）。

- **D-28:** 优先级调度（P0 任务自动标记高优先级，仅对依赖已完成的任务允许插队）。

- **D-29:** 轻量文本监控仪表盘（Markdown 表格，显示任务状态/token 消耗/预计剩余时间，可选开启）。

### Claude's Discretion

- `light-brownfield` 字段的具体阈值和触发条件由 planner 在实现阶段确定。
