开源君 *2026年4月14日 10:00*

想象一下：你写好产品需求文档（PRD），然后——什么都不用做了。AI 会自动开分支、写代码、跑测试、提交代码，直到 PRD 里的每一项都打上勾。它会在每次迭代后更新你的 `AGENTS.md` ，把踩过的坑都记下来，让下一个迭代的 AI 少走弯路。这不是科幻，这是 **Ralph** 正在做的事。

它不是又一个「AI 写代码」的工具。它是一个 **自主 Agent 循环** ：你给它一个 PRD，它会像实习生一样，一遍又一遍地调用 Claude Code 或 Amp，直到所有需求全部 `passes: true` 。

## 01 它是什么？

**Ralph** 是一个基于 Bash 的 autonomous AI agent loop，由开发者 Geoffrey Huntley 提出模式、@snarktank 开源实现。

它的核心逻辑极其简洁：

> **PRD → prd.json → 循环执行 → 全部完成 → 输出 `<promise>COMPLETE</promise>`**

每次循环，Ralph 会：

1. 从 `prd.json` 挑出优先级最高的 `passes: false` 的用户故事
2. 启动一个 **全新的 AI 实例** （Amp 或 Claude Code），带着项目上下文
3. AI 完成这一项story
4. 运行质量检查（typecheck、测试）
5. 检查通过 → 提交 commit → 标记 `passes: true`
6. 把学习到的上下文追加到 `progress.txt` 和 `AGENTS.md`
7. 重复，直到所有 story 都完成

**关键设计** ：每次迭代都是干净上下文的 AI 实例，跨迭代的记忆只靠三个东西—— **git 历史** 、 **progress.txt** 、 **prd.json** 。

---

## 02 核心原理/亮点

**每个迭代 = 全新 AI 实例**

这是 Ralph 最核心的设计哲学。传统 AI coding 会遇到「上下文耗尽」的问题——代码库太大、对话太长，AI 开始健忘、重复劳动。Ralph 的解法是： **不要试图在一个长对话里搞定一切** 。

与其让一个 AI 记住所有上下文，不如让每个迭代的 AI 都轻装上阵，通过 `progress.txt` 和 `AGENTS.md` 传递「已发现的模式」和「踩过的坑」。

**PRD 驱动，任务粒度可控**

Ralph 要求每个 PRD item 足够小——小到能在一个上下文窗口里完成。「添加一个数据库列」「在现有页面上加一个 UI 组件」——这样每个故事都是可完成的单元，不会半途而废。

**三级反馈闭环**

Ralph 的质量保证靠三层反馈：

- **Typecheck**
	拦截类型错误
- **测试**
	验证行为正确性
- **Git history**
	让下一个 AI 能看到上一个 AI 写了什么

没有反馈闭环的 AI coding 是在裸泳。Ralph 把它做扎实了。

## 03 应用场景

**谁适合用 Ralph？**

- 有明确 PRD、需要 AI 帮你完成具体功能开发的团队
- 希望 AI coding 工件能沉淀到项目文档（AGENTS.md）中的开发者
- 想把 AI 当「第二程序员」而非「代码补全器」的场景

Ralph 也支持作为 **Claude Code Marketplace 插件** 安装，安装后直接调用 `/prd` 和 `/ralph` 技能：

```
/plugin marketplace add snarktank/ralph /plugin install ralph-skills@ralph-marketplace
```

它的工作流：

```
PRD 文档 → /ralph 转换 prd.json → ./ralph.sh 启动循环 → 自动完成所有需求
```

## 04 快速上手

**第一步：安装 Claude Code 或 Amp**

```
# Claude Code npm install -g @anthropic-ai/claude-code  # 或 Amp（默认） # 参见 https://ampcode.com
```

**第二步：把 Ralph 引入你的项目**

```
# 进入你的项目根目录 mkdir -p scripts/ralph  # 复制 ralph 脚本 cp /path/to/ralph/ralph.sh scripts/ralph/  # 复制 Claude Code 用 prompt 模板 cp /path/to/ralph/CLAUDE.md scripts/ralph/  chmod +x scripts/ralph/ralph.sh
```

**第三步：生成 PRD 并转换**

在 Claude Code 里输入：

```
Load the prd skill and create a PRD for [你的需求描述]
```

回答完澄清问题后，用 `/ralph` 转换为 `prd.json` ：

```
Load the ralph skill and convert tasks/prd-[feature-name].md to prd.json
```

**第四步：启动 Ralph**

```
# 默认使用 Amp，最多 10 次迭代 ./scripts/ralph/ralph.sh  # 指定 Claude Code ./scripts/ralph/ralph.sh --tool claude  # 指定最大迭代次数 ./scripts/ralph/ralph.sh 20
```

Ralph 会输出类似这样的日志：

```
[ Ralph ] Starting iteration 1/10 [ Ralph ] Selected story: "Add dark mode toggle" [ Ralph ] Running: claude --dangerously-skip-permissions ... [ Ralph ] ✓ Checks passed. Committing. [ Ralph ] Updated AGENTS.md with discovered patterns. ... [ Ralph ] ✓ All stories complete. <promise>COMPLETE</promise>
```

## 写在最后

Ralph 让我们看到了一个更有结构的 AI coding 未来：不是给 AI 一个模糊的「帮我做这个项目」，而是把大任务拆成小的、明确的、可验证的单元，让 AI 在一次次迭代中「做完」而不是「试过」。

它的设计里有个很朴素但很重要的信念： **AI 不需要记住所有事情，但需要知道哪些事情已经做完了、哪些坑已经踩过了** 。通过 git、progress.txt 和 AGENTS.md，Ralph 把这个信念落了地。

如果你也在思考「怎么让 AI 真正帮我完成工作」而不是「帮我写代码片段」，Ralph 值得你花 20 分钟跑通一次 demo。
